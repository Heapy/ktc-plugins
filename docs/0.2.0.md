# 0.2.0 changes and verification

Implemented commands: `diff`, `outdated`, `remove`, `wrapper update --version`, and
producer `validate`. Mutation dry-runs now show source, configuration and lockfile
diffs. The existing install/update/sync safety checks still apply.

Removal supports block lists/maps and one-line flow collections. It keeps module
globs, unrelated settings and user ignore entries, comments out explicitly selected
plugin configuration, refuses source drift, and rolls back deletions on failure.
Module discovery supports root modules and registered nested/globbed modules;
wildcard scans omit build/tool state and never follow links.

Launcher updates choose an explicit published stable release and verify every
launcher and native pin. Modified/unrecognized launchers are refused. CRLF checkout
normalization is accepted. Source caches and project locks retain the 0.1.0 rules.
The release transport strips API credentials on asset-host redirects and keeps
request URLs/tokens out of process arguments.

Producer validation uses current tracked/nonignored working-tree files in Git,
checks every selected producer entry and license material, and runs the same
packaging preparation as installation. It does not build or run plugins.

Producer catalogs can also be declared through `catalog.file` and `catalog.export`.
Plugin configuration resolves producer aliases to pinned coordinates, while selected
libraries are exported into managed consumer catalog blocks. Catalog changes share
the source/lockfile transaction and are checked for drift. See the
[catalog contract](../README.md#producer-catalogs-and-exported-libraries) and
[catalog verification results](verification.md#catalog-export-extension-2026-10-08).

Each producer includes its root `LICENSE`. SQLDelight versions stay 2.3.2 and 0.7.3
as in the audited catalog. Unrelated kotgent work remains untouched. These changes
are available at their exact commits, without new upstream releases. Acceptance/runtime
scripts pin these producer commits and use manifest selection; the historical
SQLDelight catalog rejection remains a negative acceptance case.

Verification on macOS ARM64:

- 35 shared tests pass on JVM and native macOS, including Git-applicable unified
  diffs, offline read-only checks, safe removal, deletion crash recovery, root/nested
  module discovery, release tampering and launcher drift/rollback protections.
- Native release binaries compile for macOS ARM64, Linux x64, Linux ARM64 and Windows x64.
- All three actual producer repositories pass `validate` with their prepared manifests.
- The native smoke script exercises real pinned GitHub sources, offline restore,
  diff/outdated, modified-source refusal, removal, producer validation and verified
  launcher acquisition from the published 0.1.0 release.
- Generated launchers pass concurrent bootstrap/cache, path/argument forwarding,
  offline and corruption-rejection tests.
- Quarkus packaging, detekt/config execution, and SQLDelight generation/compilation
  pass after installation from the exact published producer commits and manifests.
  The adapted local SQLDelight producer also passes; neither path substitutes catalog
  aliases in the fixture or depends on the producer's root catalog.

The workflow targets 0.2.0 and runs the expanded native smoke tests on each runtime
host. The version tag builds the release bundle and prepares a draft for publication.
See [CHANGELOG.md](../CHANGELOG.md) for the complete 0.2.0 release notes.
